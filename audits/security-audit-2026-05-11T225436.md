## Findings

### 1) Legacy economy mutation responses still leak foreign-object state and exact balance detail
- **Severity:** Medium
- **Affected projects:** `projects/Api`
- **Affected surfaces:** `Mutation.BuildingMarket.cs`, `Mutation.Exchange.cs`, adjacent banking and trade flows.
- **Description:** Several economy-sensitive mutations still return distinct state-revealing codes such as `COMPANY_NOT_FOUND`, `BANK_ACCOUNT_NOT_FOUND`, `BANK_ACCOUNT_MISMATCH`, `BUILDING_NOT_FOR_SALE`, and exact affordability details such as `Available: ...` and `Required: ...`. OWASP API1:2023 highlights that every function using client-supplied object identifiers should enforce object-level authorization consistently and that response differences materially lower the cost of probing unauthorized objects.
- **Evidence:** `MakeOfferOnBuilding` still exposes buyer-company existence and exact available balance text. `BuyFromExchange` and `SellToExchange` still distinguish unit ownership, account presence, company linkage, and exact balance or inventory thresholds instead of collapsing foreign-object failures to a redacted ownership failure.
- **Potential impact:** An authenticated competitor can use mutation probing to infer whether a rival company exists, whether a building is listed, whether a bank account is linked to a company, and how close an opponent is to a funding threshold.
- **Status:** Open

### 2) `projects/master-frontend` still carries a moderate `postcss` production advisory
- **Severity:** Medium
- **Affected projects:** `projects/master-frontend`
- **Description:** `npm audit --omit=dev` reports `postcss < 8.5.10` with `GHSA-qx2v-qp2m-jg93` / `CVE-2026-41305`. GitHub Advisory Database describes an XSS condition when user-submitted CSS is parsed and re-stringified into an HTML `<style>` tag without escaping `</style>`. I did not confirm a reachable user-controlled CSS stringify path in this repository, so this remains an operational dependency risk rather than an active exploit path.
- **Evidence:** Fresh local audit output still recommends `npm audit fix` and the patched version is `8.5.10`.
- **Potential impact:** If a future feature introduces CSS parsing or stringify flows with user-controlled CSS, the outdated dependency could become a reachable XSS primitive.
- **Status:** Open

### 3) Previously open MasterApi news trust-boundary risk is now mitigated and regression-tested
- **Severity:** Resolved
- **Affected projects:** `projects/MasterApi`, `projects/MasterApi.Tests`
- **Description:** The news feed and news upsert surfaces no longer trust caller-supplied requester identity. Draft visibility is now derived from trusted game-server credentials or authenticated privileged admin claims, and `UpsertGameNewsEntry` explicitly rejects caller-supplied `RequesterEmail`.
- **Evidence:** `GetGameNewsFeed` now gates draft inclusion behind trusted server or privileged admin resolution; `UpsertGameNewsEntry` throws `REQUESTER_EMAIL_NOT_ALLOWED` when the caller supplies requester identity. `MasterApiIntegrationTests` contains dedicated coverage for spoofed requester rejection, service-derived author identity, sanitized HTML, public feed draft exclusion, and trusted draft visibility.
- **Status:** Resolved

### 4) Support-ticket preview sanitization is now allowlist-based and covered by payload regression tests
- **Severity:** Resolved
- **Affected projects:** `projects/MasterApi`, `projects/MasterApi.Tests`, `projects/Shared`
